# Lock file for concurrent cake processes

Problem: parallel commands fail on git's index.lock and leave files uncommitted, or overwrite each other's change on the same item ([[2wkhyp]]).

- `.cake/.lock`, OS file lock (`fd-lock`), released by the OS on crash
- held from store load to commit
- shared for read-only commands, exclusive for changing commands and sync
- busy → print "waiting for lock" on stderr once, then block
- interactive `cake edit` does not hold it while the editor is open ([[0qwtxm]])
- test: 20× two parallel adds → all items committed, no errors
